FuelMap · iOS · Visual restyle

Find the cheapest fuel, at a glance.

A bold, energetic restyle for FuelMap — Italy's MIMIT-powered fuel-price map. Built entirely from native SwiftUI components and a semantic token set, engineered for a glanceable, in-the-car context. Blue leads; price still speaks in green / orange / red — never by color alone.

SwiftUI-native Light + Dark parity WCAG AA Colorblind-safe tiers Dynamic Type SF Pro · monospaced prices
Overview

Intent & principles

This is a restyle of the visual layer of an app that already works. Every decision below maps to a SwiftUI semantic Color asset, an SF Symbol, or a standard component — nothing here requires re-architecture or custom rendering.

Glance, don't read

Primary context is in or before the car. The cheapest option must resolve in a single look: color tier + shape + position all point the same way.

Solid over live tiles

Everything floats over an arbitrary MapKit map. Pins, banners and controls use opaque fills, a contrasting stroke and a shadow — contrast never depends on the map.

Blue is the brand

Azure carries navigation, controls, selection and CTAs — trust, maps, data. The three price tiers are deliberately tuned to stay distinct from it.

Reading this doc. Every swatch and contrast ratio is read live from tokens.css and computed in the browser, so the documentation can't drift from the implementation. The phone mockups are the same components you see in the spec, themed by a single data-theme attribute.
The system

How the price tier survives a restyle

The non-negotiable constraint: cheap / mid / expensive must be instantly separable from each other, from brand blue, and for colorblind users. We never lean on hue alone — four redundant signals always agree.

①

Hue

Green · burnt-orange · red, tuned away from blue.

②

Shape

▲ low · ● mid · ▼ high — the same glyph on pins, rows and detail.

③

Label

A text tag (BASSO / MEDIO / ALTO) wherever space allows.

④

Position

Cheapest is ranked first & crowned; lists sort by price.

Foundations

Color tokens

Semantic names first, raw hex alongside — each pair shows its Light and Dark value and, where it carries text, the live-computed contrast ratio and WCAG grade.

Brand ramp — azure

The anchor is brand-500 #0091FF. Tints come from the upper ramp; solid CTAs use brand-600 so a white label clears AA.

Price tiers — fills are identical in both modes

Tier fills don't flip between modes: white pin text keeps its contrast and a green pin stays "green" whichever theme you're in. Only the ink (tier color used as text on a surface) brightens for dark. Components

Price pin

The atom of the map. A capsule that reads instantly over any tile: a white-framed brand badge, a tier shape (▲ ● ▼), the price in tabular digits, and a pointer tail — all on an opaque tier fill with a contrasting halo and shadow.

Anatomy

  • Badge (28pt) — white circle framing the brand logo / monogram, a ★ if cheapest, or a fuel-pump glyph for pompe bianche.
  • Tier shape — ▲ low · ● mid · ▼ high. The colorblind-safe redundancy; never optional.
  • Price — 15pt Semibold, tabular digits, €/L 3-decimal, white.
  • Halo + tail — 2pt stroke (white in light, near-black in dark) + drop shadow lift it off the map.
  • Touch target — visual height 34pt; tappable area padded to ≥44×44pt.

Brand chip

A neutral frame that makes any brand logo legible on map or sheet: a surface-colored rounded rect with a hairline, fixed height, generous padding. Logos drop in at their native colors; unknown brands (pompe bianche) get a monogram or a generic pump glyph. In these mockups the monogram stands in for the real trademarked logo.

Accessibility

Accessibility is a functional requirement here, not a polish pass — the app is used at a glance, often in motion. Every ratio below is computed live in your browser from the real tokens.

Contrast results

PairLightDarkMin

AA = 4.5:1 (normal text) / 3:1 (large or UI). Pin prices are bold and treated as large text; all tier fills clear the large-text floor with margin.

Colorblind strategy for the price tiers

The problem: green vs red is exactly the deuteranopia / protanopia confusion axis. The rule: hue is never the only signal — three more always agree.

TierHueShapeLabel
Cheapgreen▲ upBASSO
Midorange● dotMEDIO
Highred▼ downALTO

Why it holds under CVD

  • The shape (▲ ● ▼) is unambiguous without any color and points the way value moves.
  • The word appears on every row, in the detail sheet, and on the selected pin.
  • Position reinforces it — price-sort puts cheap on top; the single cheapest is crowned with a gold ★.
  • Tiers are also tuned for luminance separation, so they differ in greyscale, not just hue.

Dynamic Type & motion

Dynamic Type

Every role maps to a built-in iOS text style and scales with the user's setting. Sheet and list text scale fully and reflow to multiple lines instead of truncating; the pin price uses a capped style so a pin can't outgrow its footprint over the map.

Reduce Motion

Honors prefers-reduced-motion: the loading spinner slows and the skeleton shimmer stops, pins place instead of bouncing, and sheet transitions cross-fade rather than spring.

Targets & VoiceOver

All interactive elements are ≥44×44pt. Pins announce the full picture — "Q8, benzina self 1,789 € al litro, più economica, 0,8 km" — so tier, rank and price never depend on sight of color.

A copy-friendly export of the semantic color tokens for both modes — generated live from tokens.css. Drop these into a SwiftUI semantic Color asset catalog (Any / Dark appearances) and a tokens file; the CSS custom-property names map 1:1 to asset names.
